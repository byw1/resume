Why it exists

You have done more than you can remember, and the resume is written from memory.

Every search starts the same way: a blank document, a vague recollection of what the last three years were, and a number you can't source. The material was never the problem — it was never written down anywhere durable. Hired is that place, and the assistant that reads it back to you when it matters.

The read

It tells you which step is losing people.

Every other tracker shows you six numbers and leaves the interpreting to you. Hired states the problem in a sentence, marks the step that is failing, and shows its working underneath — including which of your resumes is actually getting answers.

Under ten applications it says "Too early to tell you anything useful." and nothing else. A diagnosis from four data points is a guess wearing a lab coat.

The rule the whole thing is built on

Nothing on a resume is invented.

Every client that connects is handed the same instruction before it can call anything: never invent experience, employers, dates or metrics. Every bullet has to trace back to something you wrote down — and when a posting asks for evidence you don't have, it says so instead of writing it anyway.

The quiet upgrade is the failure that actually happens. A credit becomes a hire, a "helped with" becomes a "led", and none of it feels like invention to whoever is drafting, because every upgrade maps to a stated responsibility. That is the specific thing this refuses to do.

Works where you already talk

Setup is one paste, and it's the same paste everywhere.

Each app you connect gets its own private link, with the exact steps shown inside Hired. Lose the laptop with one of them on it and you revoke that link alone — the others keep working.

For anyone who wants the detail: it's a stateless Streamable HTTP MCP server. Every request stands alone, so there's no session to keep alive and nothing to reconnect after a restart.

  1. Open Claude and go to Settings → Connectors.

  2. Click "Add custom connector".

  3. Name it Hired and paste your connection URL:

    Connection URL
    https://app.hired.tools/api/mcp/<your token>

  4. Save. Claude can now read and write your brain, resumes and pipeline.

  1. Run this anywhere. --scope user makes it available in every project:

    Terminal
    claude mcp add --transport http --scope user hired "https://app.hired.tools/api/mcp/<your token>"

  2. Check it took with claude mcp list — it should say ✔ Connected.

  1. Add this to ~/.cursor/mcp.json to get it everywhere, or .cursor/mcp.json inside a project to scope it there:

    ~/.cursor/mcp.json
    {
  "mcpServers": {
    "hired": { "url": "https://app.hired.tools/api/mcp/<token>" }
  }
}

  2. Reopen Cursor. The server shows up under Settings → MCP.

  1. Add it from the terminal:

    Terminal
    code --add-mcp '{"name":"hired","type":"http","url":"https://app.hired.tools/api/mcp/<token>"}'

  2. Or commit it to a project by hand:

    .vscode/mcp.json
    {
  "servers": {
    "hired": { "type": "http", "url": "https://app.hired.tools/api/mcp/<token>" }
  }
}

  1. Most clients take some version of this. If yours wants a transport name, it's Streamable HTTP:

    Config
    {
  "mcpServers": {
    "hired": {
      "type": "streamable-http",
      "url": "https://app.hired.tools/api/mcp/<token>"
    }
  }
}

  2. If it insists on an Authorization header instead of a token in the URL, drop the token from the path and send it as a bearer. If it only speaks stdio, npx -y mcp-remote <url> bridges it — so "my client isn't listed" is never a dead end.

  3. Or call it yourself. It's JSON-RPC 2.0 over POST, with no session handshake to keep alive:

    Terminal
    curl -s $URL -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'

Before you ask

The questions that come up.

Do I need Claude to use it?

No. The web app is complete on its own — you can write your brain, build resumes, export PDFs and run the pipeline without ever connecting an assistant. But the product was designed conversation-first, and roughly everything gets faster when you can say "file this" instead of opening a form.

Who can see what I write?

On your own instance, you. On the hosted one, you — admins manage accounts, never content, and there is no code path that lets one person read another's brain, resumes or applications. Every data function takes the owning user id as its first argument, which is what makes that a compile-time property rather than a promise.

The one deliberate exception is a resume you publish. That page is readable by anyone holding its link, and it is the only anonymous read in the system.

Is a published resume link actually private?

It's unlisted, not secret. The slug carries about sixty bits of entropy so it can't be guessed, and the page tells search engines not to index it. There are no per-viewer permissions, because everyone you'd send it to is someone you already decided to send it to.

Withdrawing a link destroys the address rather than pausing it. Publishing again gives you a different one — the reason you withdraw a link is usually that it went somewhere you regret, and a pause you can undo doesn't fix that.

Will the PDF get through an ATS?

The document is real text in a real page, not an image, and the default template is a faithful port of the Harvard OCS format — everything one size, no colour, no columns. The PDF is rendered headless from that same page, so what you see is what gets parsed.

What happens if I stop paying?

Your workspace is suspended, not deleted. The self-hosted build is the same build, so moving to your own instance is always available and never a downgrade.

How much does self-hosting actually cost to run?

An app container and a Postgres. It runs on the smallest box any host sells. There is one required environment variable — DATABASE_URL — and everything else is configured inside the app, so there is no second config file to keep in sync.

Can I get my data out?

It's your Postgres. pg_dump it. On the hosted instance, get_brain_snapshot returns the entire knowledge base in one call, and every resume exports as a PDF.
