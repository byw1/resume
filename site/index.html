Applicant’s Tracking System

We are building the ATS for Applicants. Every company you apply to runs on an ATS. Theirs keeps a record on you, scores what you sent and decides what happens next — and you never get to see it. This one keeps the record on them: what you've actually done, what you sent where, and who still owes you an answer.

Why it exists

They have a system. You have a folder called final_v3.

On their side of the application is software that has been keeping score since the first time you applied: what you sent, when, against which req, and what the recruiter typed afterwards. On your side there's a resume written from memory, a spreadsheet you stopped updating in March, and three years of work you can no longer describe in detail. Nobody loses a job to a better candidate as often as they lose it to that gap.

The read

Recruiters get a funnel report. Now you get one.

Theirs says where candidates drop out. Yours says where you do — and unlike the six numbers every other tracker leaves you to interpret, it states the problem in a sentence, marks the step that is failing, and shows its working underneath, including which of your resumes is actually getting answers.

Under ten applications it says "Too early to tell you anything useful." and nothing else. A diagnosis from four data points is a guess wearing a lab coat.

The rule the whole thing is built on

Nothing on a resume is invented.

Every client that connects is handed the same instruction before it can call anything: never invent experience, employers, dates or metrics. Every bullet has to trace back to something you wrote down — and when a posting asks for evidence you don't have, it says so instead of writing it anyway.

The quiet upgrade is the failure that actually happens. A credit becomes a hire, a "helped with" becomes a "led", and none of it feels like invention to whoever is drafting, because every upgrade maps to a stated responsibility. That is the specific thing this refuses to do.

Works where you already talk

Setup is one copy and paste, and it's the same one everywhere.

Each app you connect gets its own private link, with the exact steps shown inside Hired. Lose the laptop with one of them on it and you revoke that link alone — the others keep working.

For anyone who wants the detail: it's a stateless Streamable HTTP MCP server. Every request stands alone, so there's no session to keep alive and nothing to reconnect after a restart.

  1. Open Claude and go to Settings → Connectors.

  2. Click "Add custom connector".

  3. Name it Hired and paste your connection URL:

    Connection URL
    https://app.hired.tools/api/mcp/<your token>

  4. Save. Claude can now read and write your career history, resumes and pipeline.

  1. Run this anywhere. --scope user makes it available in every project:

    Terminal
    claude mcp add --transport http --scope user hired "https://app.hired.tools/api/mcp/<your token>"

  2. Check it took with claude mcp list — it should say ✔ Connected.

  1. Add this to ~/.cursor/mcp.json to get it everywhere, or .cursor/mcp.json inside a project to scope it there:

    ~/.cursor/mcp.json
    {
  "mcpServers": {
    "hired": { "url": "https://app.hired.tools/api/mcp/<token>" }
  }
}

  2. Reopen Cursor. The server shows up under Settings → MCP.

  1. Add it from the terminal:

    Terminal
    code --add-mcp '{"name":"hired","type":"http","url":"https://app.hired.tools/api/mcp/<token>"}'

  2. Or commit it to a project by hand:

    .vscode/mcp.json
    {
  "servers": {
    "hired": { "type": "http", "url": "https://app.hired.tools/api/mcp/<token>" }
  }
}

  1. Most clients take some version of this. If yours wants a transport name, it's Streamable HTTP:

    Config
    {
  "mcpServers": {
    "hired": {
      "type": "streamable-http",
      "url": "https://app.hired.tools/api/mcp/<token>"
    }
  }
}

  2. If it insists on an Authorization header instead of a token in the URL, drop the token from the path and send it as a bearer. If it only speaks stdio, npx -y mcp-remote <url> bridges it — so "my client isn't listed" is never a dead end.

  3. Or call it yourself. It's JSON-RPC 2.0 over POST, with no session handshake to keep alive:

    Terminal
    curl -s $URL -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'

Before you ask

The questions that come up.

Do I need to be technical to use this?

No. On the hosted version you get a link, pick a password, and you're in — it's a website. The only setup is pasting one address into Claude or ChatGPT, and that screen gives you the address and tells you where it goes. Self-hosting is the part that needs a terminal, and it's optional.

Can I use it now?

You can self-host it now — that's finished and free. Hosting is invite-only while I let people in a few at a time and fix what they find. Put your email in the box and I'll send you an invite when a place opens; nothing else happens to your address.

What does it cost?

Nothing if you run it yourself, forever. Hosted is $12 a month, or $120 a year, which is two months off for paying up front. Cancel whenever you like. There's no free trial of the hosted plan because self-hosting is the free version, and it's the same software rather than a cut-down one.

Will it invent things to put on my resume?

No, and that's the rule the whole thing is built on. Every connected assistant is told, in writing, never to invent an employer, a date, a title or a number. If a posting wants something you haven't got, it says so and asks you rather than filling the gap. There's a section above showing exactly what that refusal looks like.

How long until it's useful?

One job. Write down what you actually did at one place you can still remember, in whatever order it comes out, and you can produce a tailored resume from it that afternoon. It gets better every time you add something, which is the point — but it does not need your whole life before it does anything.

Do I have to talk to an AI to use it?

No. Everything has a screen: Me, the resume editor, the board, the contacts. Talking to it is faster for the boring parts — logging what happened, moving a card, tailoring a resume — and the two are the same data, so you can do a thing by hand and ask about it a minute later.

Will the PDF get through an ATS?

The document is real text in a real page, not an image, and the default template is a faithful port of the Harvard OCS format — everything one size, no colour, no columns. The PDF is rendered from that same page, so what you see is what gets parsed.

Who can see my stuff?

You. Every workspace is private, including from whoever runs the instance — admins manage accounts, never content, and that's enforced in the code rather than by policy. The one exception is a resume you deliberately publish as a link, and you choose when that happens and can unpublish it.

What happens if I stop paying, or you stop caring?

Stop paying and your workspace is suspended, not deleted. If I disappear, the software is AGPL-3.0 and the self-hosted build is the same build, so moving to your own instance is always available and never a downgrade. It's your Postgres either way — pg_dump it, or ask for everything back in one call.
